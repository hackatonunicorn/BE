# 🔐 Отчет о системе аутентификации

## Обзор

Создана полнофункциональная система аутентификации для Startup VC Platform с современным пользовательским интерфейсом, JWT токенами и защищенными API endpoints.

## 🏗 Архитектура системы

### Компоненты

1. **Модели данных** (`app/data/models.py`)
   - `User` - основная модель пользователя
   - `UserRole` - роли пользователей (startup, vc_fund, admin)
   - Связи с существующими моделями (Startup, VCFund)

2. **Система аутентификации** (`app/core/auth.py`)
   - JWT токены (access + refresh)
   - Хеширование паролей (bcrypt)
   - Middleware для защиты endpoints
   - Роли и разрешения

3. **API Endpoints** (`app/api/auth.py`)
   - Регистрация пользователей
   - Вход в систему
   - Обновление токенов
   - Управление профилем
   - Смена пароля

4. **Пользовательский интерфейс**
   - Страница входа (`/login`)
   - Страница регистрации (`/register`)
   - Dashboard (`/dashboard`)
   - Главная страница (`/`)

## 🔑 Функциональность

### Регистрация пользователей

**Endpoint:** `POST /api/auth/register`

**Функции:**
- Валидация email и пароля
- Автоматическая генерация username
- Хеширование пароля
- Создание JWT токенов
- Поддержка разных ролей

**Валидация пароля:**
- Минимум 8 символов
- Заглавная буква
- Строчная буква
- Цифра

### Вход в систему

**Endpoint:** `POST /api/auth/login`

**Функции:**
- Аутентификация по email/паролю
- Генерация access и refresh токенов
- Опция "Remember me"
- Обновление времени последнего входа

### Управление токенами

**Access Token:**
- Срок действия: 24 часа (настраивается)
- Содержит: user_id, email, role
- Используется для API запросов

**Refresh Token:**
- Срок действия: 30 дней
- Используется для обновления access token
- Автоматическое продление сессии

### Защищенные endpoints

**Middleware защиты:**
- `get_current_user()` - получение текущего пользователя
- `get_current_active_user()` - только активные пользователи
- `require_startup_role()` - только стартапы
- `require_vc_role()` - только VC фонды
- `require_admin_role()` - только администраторы

## 📊 База данных

### Таблица `users`

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    full_name VARCHAR(100) NOT NULL,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    company_name VARCHAR(100),
    hashed_password VARCHAR(255) NOT NULL,
    role userrole NOT NULL DEFAULT 'startup',
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    is_verified BOOLEAN NOT NULL DEFAULT FALSE,
    is_superuser BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    last_login TIMESTAMP
);
```

### Связи
- `startups.owner_id` → `users.id`
- Поддержка ролей через enum

## 📱 Пользовательский опыт

### Поток регистрации

1. Пользователь заходит на главную страницу
2. Нажимает "Get Started" или "Create Account"
3. Заполняет форму регистрации
4. Система валидирует данные
5. Создается аккаунт
6. Автоматический вход в систему
7. Перенаправление на dashboard

### Поток входа

1. Пользователь заходит на страницу входа
2. Вводит email и пароль
3. Опционально выбирает "Remember me"
4. Система аутентифицирует пользователя
5. Создаются JWT токены
6. Перенаправление на dashboard

### Управление сессией

- Access token хранится в localStorage
- Refresh token используется для продления сессии
- Автоматический logout при истечении токенов
- Защищенные страницы перенаправляют на login
